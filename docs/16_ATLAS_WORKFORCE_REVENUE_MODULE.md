# Atlas Workforce — Revenue Module

## Goal

Expose ARO as an operational department inside Atlas Workforce.

The user should experience Revenue as another operating capability beside marketing, attendants and project management.

## Primary navigation

- Revenue Overview
- Sales
- Orders
- Payments
- Customers
- Offers
- Providers
- Routing
- Entitlements
- Refunds
- Reconciliation
- Settlements
- Reports
- Finance Operator

## Dashboard

### Executive
- gross revenue
- net revenue
- orders
- paid conversion
- AOV
- refunds
- provider fees
- revenue by project
- revenue by market/currency

### Operations
- pending/failed payments
- webhook errors
- reconciliation exceptions
- provider health
- settlement status

### Growth
- funnel conversion
- revenue by campaign
- bump/upsell conversion
- LTV
- product revenue mix

## Agent panel

The Finance/Revenue Operator appears as a Workforce agent with:
- current health summary;
- alerts;
- pending recommendations;
- reconciliation queue;
- research findings;
- requested approvals.

## Client mode

For selected AtlasHub clients, the same UI can be tenant-scoped.

Client operators see only permitted project/business-unit data.

## Human + Agent

The objective is not to hide finance behind automation.

The desired operating model is:
```
Dashboard + Structured Data + Agent Analysis + Explicit Controls
```

This gives humans immediate visibility while letting Hermes continuously watch the system.
